# STP と競合分析、マーケティング計画（2026-09-05）

**種別: アイディアドキュメント（記録）。正本ではない。**
確定した内容は `README.md` と `docs/human-review/roadmap.md` へ移す。

競合の事実は 2026-09-05 に実地で確認した。出典は末尾。

---

## 1. 結論から

**「マインドマップツール」として売ると負ける。** 機能量では XMind に、
Markdown 編集では Obsidian に、それぞれ勝てない。

**勝てる位置は「AI に渡す下書きを、`.md` のまま組み立てる場所」である。**
この位置を名乗っている競合はいまのところ無い。

狙う相手は **「プレーンテキストで書き、AI を日常的に使い、GitHub アカウントを持つ人」**。
GitHub アカウントが要るという参入障壁が、そのまま相手の絞り込みになっている。

---

## 2. Segmentation — 市場をどう切るか

マインドマップ利用者を、**保存形式へのこだわり**と**主用途**の2軸で切る。
この2軸を選んだのは、Mieru の設計判断（Markdown が保存形式）が効くかどうかが
ここで決まるからである。

| | 思考整理が主 | 清書・共有が主 |
|---|---|---|
| **ロックインを嫌う** | **S1・S2** ← ここが Mieru の市場 | S3 |
| **気にしない** | S4 | S5 |

| # | セグメント | 特徴 | 規模の感触 |
|---|---|---|---|
| S1 | **AI ヘビーユーザー** | 企画・PM・コンサル・エンジニア。AI に投げる前の構造化に困っている。プロンプトが長文になりがち | 拡大中 |
| S2 | **プレーンテキスト PKM 利用者** | Obsidian / Logseq。`.md` で持つことに価値を置く。マインドマップ拡張に不満がある | 中・熱量が高い |
| S3 | **エンジニア／テクニカルライター** | VS Code と GitHub で文書を書く。設計の下書きに使いたい | 中 |
| S4 | **一般のマインドマップ利用者** | XMind・MindMeister。見た目と機能量を重視 | 最大 |
| S5 | **学生・読書メモ** | 無料であることが最優先 | 大 |

---

## 3. Targeting — 誰を狙うか

**一次: S1 ∩ (S2 ∪ S3)。** AI を日常的に使い、かつプレーンテキストで書く人。

理由は3つある。

- **参入障壁が既にフィルタになっている。** 保存先に GitHub リポジトリを使うため、
  この層以外は最初の1歩で脱落する。**間口を広げようとするより、
  通れる人に深く刺さる方が費用対効果が高い**
- **トークンと CSP の説明が通じる。** Mieru の信頼の説明（外部リソースを読み込まない、
  通信先が1つ）は、この層にしか価値が伝わらない
- **拡散力がある。** 技術系は使ったものを書いて共有する

**二次: S2 単独（Obsidian 利用者）。** vault のフォルダをそのまま保存先にできる点は、
説明が1行で済む強い訴求である。

**狙わない: S4・S5。** 機能量と無料枠で戦うことになり、勝てない。

---

## 4. Positioning — 何として憶えてもらうか

> **AI に渡す下書きを、`.md` のまま組み立てる場所。**

補助となる主張は4つ。**どれも競合が主張していないものだけを選んだ。**

| # | 主張 | 競合が言えない理由 |
|---|---|---|
| 1 | **書き出す工程が無い。** Markdown が保存形式そのもの | 専用ツールは独自形式で、Markdown は書き出し機能。XMind は Markdown 書き出しが有料 |
| 2 | **開いて保存しても中身が変わらないことを、テストで保証している** | この保証を明示しているツールを見つけられなかった |
| 3 | **インストールもアカウント登録も要らない。** ブラウザだけで、スマホでも同じファイル | Obsidian 拡張はアプリが要る。VS Code 拡張はスマホで動かない |
| 4 | **サーバもデータベースも無い。** ファイルは利用者のリポジトリにある | SaaS 型の競合は原理的に言えない |

**「マインドマップツールです」と名乗らない。** そう言った瞬間に S4 の土俵で比較され、
機能量で負ける。名乗るのは**用途**である。

## 5. 競合の実地調査（2026-09-05）

### 5.1 比較表

| | 図として編集 | 保存形式 | アプリ無しで開ける | スマホ | 費用 | 状態 |
|---|---|---|---|---|---|---|
| **Mieru** | ✅ | **`.md` そのもの** | ✅ ブラウザのみ | ✅ | 無料 | 単一開発者・実績なし |
| XMind | ✅ 強い | `.xmind`（独自） | ❌ | ✅ アプリ | 無料枠は10マップ。Markdown 書き出しは有料 | 商用・成熟 |
| MindMeister | ✅ 強い | クラウド（独自） | ❌ | ✅ アプリ | 無料枠あり | 商用・成熟 |
| markmap（本体） | ❌ 表示のみ | `.md` を読む | ✅ | △ | 無料 | 活発 |
| VS Code + markmap 拡張 | ❌ 表示のみ | `.md` を読む | ❌ VS Code が要る | ❌ | 無料 | 活発 |
| VS Code + Markdown Preview Enhanced | ❌ 表示のみ | `.md` を読む | ❌ | ❌ | 無料 | 活発 |
| Obsidian + Mind Map（markmap） | ❌ 表示のみ | `.md` を読む | ❌ Obsidian が要る | ✅ | 無料 | 活発 |
| Obsidian + Enhancing Mindmap | ✅ | `.md` を編集 | ❌ | ✅ | 無料 | **最終更新が約3年前。未解決 issue 94件** |
| Obsidian + Simple Mindmap（ObsiMap） | ✅ | 取り込み・書き出しで受け渡す（保存形式は非公開） | ❌ | ✅ | 無料 | 活発（2026-07 更新） |
| Obsidian Canvas | ✅ 自由配置 | **`.canvas`（JSON）** | ❌ | ✅ | 無料 | 公式・活発 |
| Logseq | ✅ アウトライン | `.md` | ❌ | ✅ | 無料 | 活発 |

### 5.2 この表から読めること

**「図として編集できる」と「`.md` が保存形式」を両立しているものは、ごく少ない。**
表の中では Mieru と Enhancing Mindmap の2つだけである。

**その Enhancing Mindmap は約3年更新が止まっている。** ダウンロード 23万件に対し
未解決 issue が94件あり、作者は Obsidian 1.4.0 向けと注記したまま離れている。
**23万件がダウンロードした需要が、いま宙に浮いている。**

**Obsidian 公式の Canvas は JSON である。** Obsidian は「あなたのファイルはあなたのもの」を
掲げているが、Canvas の保存形式は `.canvas`（JSON Canvas）で Markdown ではない。
**図として整理した結果を Markdown で持ちたい需要は、公式では満たされない。**

**VS Code 側は表示専用しか無い。** 調べた拡張は全て、Markdown を編集して
プレビューで図を見る形である。図を触って構造を変えるものは見つからなかった。

### 5.3 Mieru が勝てない点（正直に）

**これを隠すと、使い始めた人が最初の30分で失望する。**

| 相手 | 勝てない点 |
|---|---|
| XMind・MindMeister | 見た目、テンプレート、画像、プレゼン、印刷、共同編集。**機能量では話にならない** |
| Obsidian 全般 | 全文検索、バックリンク、プラグイン、コミュニティの厚み |
| Obsidian Canvas | 自由配置。Mieru は木構造しか扱わない |
| Logseq | アウトライナーとしての完成度、日次ノート |
| どれとも比べて | **実績と信用。** 単一開発者、利用者はほぼ1人、まだライセンスも無い |

### 5.4 Mieru 固有の弱み

| 弱み | 影響 | 対処 |
|---|---|---|
| 引用（`>`）とコードブロックが保存時に失われる | 他人の `.md` を開くと消える | **README に明記する。** 逐語保持は未着手 |
| エスケープが往復しない | 同上 | 同上（`docs/ideas/2026-09-04-escape-roundtrip.md`） |
| トークンが平文で IndexedDB に入る | 端末を取られると読める | 権限と期間を絞る案内。README に明記済み |
| ローカルフォルダは Edge / Chrome 限定 | Firefox・Safari の人は GitHub 一択 | 仕様として明示 |
| GitHub アカウントが実質必須 | S4・S5 が入れない | **狙わないと決めた** |

## 6. マーケティング計画

**方針: 広く浅くではなく、狭く深く。** 狙う層が技術系なので、
届く場所が限られている代わりに、届けば読み込まれる。

### 6.1 まず整えるもの（これが無いと何をしても効かない）

| # | 打ち手 | なぜ |
|---|---|---|
| 1 | **ライセンス** | 無ければ法的に「使ってはいけない」。全ての前提 |
| 2 | **英語の README** | 狙う層の情報源は英語である |
| 3 | **30秒の動画か GIF** | 「`.md` が保存形式」は文章では伝わらない。**マップを編集 → `.md` が変わる → エディタで開く、を1本で見せる** |
| 4 | **比較表を README に載せる** | 検索して来る人は必ず「Obsidian の拡張と何が違うのか」を考える |
| 5 | **できないことの明示** | 期待値の管理。**弱みを先に言う方が信用される** |

### 6.2 どこに置くか

| 場所 | 狙う層 | 出し方 |
|---|---|---|
| GitHub の topics と Discussions | S1・S3 | `markdown` `mindmap` `pwa` `ai` `obsidian` `note-taking` |
| Obsidian フォーラム / r/ObsidianMD | **S2** | 「vault のフォルダをそのまま保存先にできる」1点で書く。**プラグインではないことを最初に断る** |
| Hacker News（Show HN） | S1・S3 | **「Markdown が保存形式である」設計判断を主題にする。** 機能紹介にしない |
| r/LocalLLaMA・AI 系コミュニティ | **S1** | 「プロンプト前の構造化」の文脈で |
| Zenn / Qiita | 日本の S1・S3 | **往復のバイト一致をどうテストしたか**は技術記事になる |
| markmap のコミュニティ | S3 | 記法互換であることを伝える |

### 6.3 語り口

**機能を並べない。困りごとから入る。**

- ✅「AI に相談したいのに考えがまとまらない」→ 解決の形を見せる
- ❌「マインドマップが描けます、Markdown で保存できます、PWA です」

**設計判断を主題にできるのがこのプロジェクトの強みである。**
「なぜ Markdown を保存形式にしたのか」「往復のバイト一致をどう保証したか」
「なぜ専用 Organization から配信するのか」は、そのまま読み物になる。
**技術系のコミュニティは、機能一覧より判断の理由を読む。**

### 6.4 測り方

**数字を目標にしない。** 個人プロジェクトで star 数を追うと、
作るものが歪む。**見るのは「使われ続けているか」だけにする。**

| 見るもの | どう取るか |
|---|---|
| Issue と Discussion の中身 | 質問の種類が「使い方」から「こう使いたい」へ移れば刺さっている |
| **自分が使い続けているか** | 成功基準 S-1・S-4（`roadmap.md`）。**これが最優先** |
| fork のうち自己ホストしているもの | 信頼の説明が効いているかの指標 |

---

## 7. 判断が要る点

1. **英語を先にするか、日本語を先にするか。** 狙う層は英語圏が厚いが、
   作者の一次コミュニティは日本語である。**日英併記より、英語 README ＋
   日本語版へのリンクを勧める**（併記は両方が古くなる）
2. **Obsidian プラグイン版を作るか。** S2 への到達は劇的に楽になるが、
   「アプリ無しで開ける」という強みを自ら捨てることになる。**当面は作らない方に寄る**
3. **公開の時期。** 引用とコードブロックの喪失を直してから出すか、
   明記した上で先に出すか。**明記して先に出す方を勧める**（使われないと何も分からない）
