以下は「分かっていること」「試して効かなかったこと」「次にやること」の記録である。

**症状**

- 子・孫を畳んだ状態では中心テーマが中央にあるように見える
- **展開すると中央に来ない。** ⛶ を押しても来ない
- サイドバーで別のマップに切り替えても来ない
- 主表示の下に「地図の外」が残る
- 入力中に地図が飛ぶことは無い（この点だけは保てている）

**実測して確かなこと**

- `.map-canvas` は `width: fit-content` で高さも内容なり。**その外側は
  `.map-container` の背景がそのまま見える**
- `mind-elixir` の暗色テーマは `--bgcolor: #252526`、こちらは `--bg: #16181d`。
  **スクリーンショットに出る境目は `.map-container` の下端を指している**
- 境目の位置は**内容の高さに追随する**（畳むと上がり、展開すると下がる）
- `refresh()` は `layout()` と `linkDiv()` だけで**中央寄せをしない**。
  マップの切り替えは `refresh()` を通る
- `toCenter()` は `transform-origin` を縦 50% に固定したまま `offsetTop` から
  位置を組み立てる。**拡大率が 1 でなく、中心テーマが地図の縦中心にないとずれる**
- `scaleFit()` の縦比は `nodes.offsetHeight / container.offsetHeight` で、
  `n = 1 / Math.max(1, ...)`。**入れ物が内容なりだと比が約1になり縮小が掛からない**

**試して効かなかったこと**（コミット `d0ed415` `6541f7d` `4fdb3da`）

1. `ResizeObserver` で大きさが変わったら中央へ寄せ直す
2. `scaleFit()` の後に入れ物の `scrollTop` / `scrollLeft` を戻す
3. 中央寄せを式ではなく `getBoundingClientRect()` で測って `move()` で詰める（`centerMap()`）
4. `.workarea` に `grid-template-rows: minmax(0, 1fr)` を足して高さの連鎖を確定させる

**次に着手する人がまずやること: 推測で直さない。実測値を取る。**

**この4回はすべて「コードを読んで立てた仮説」であり、ブラウザでの寸法を1度も
測っていない。** それが遠回りの原因である。開発者ツールの console で次を実行し、
**数値を記録してから**手を入れること。

```js
const c = document.querySelector('.canvas');
const m = document.querySelector('.map-container');
const n = document.querySelector('me-nodes');
console.table({
  canvas: c.getBoundingClientRect(),
  container: m.getBoundingClientRect(),
  nodes: n.getBoundingClientRect(),
  scroll: { top: m.scrollTop, left: m.scrollLeft },
  transform: getComputedStyle(document.querySelector('.map-canvas')).transform,
});
```

**見るべき点**

- `container` の高さが `canvas` と一致しているか（違えば高さの連鎖がまだ切れている）
- `nodes` の中心が `container` の中心と一致しているか（違えば位置の問題）
- `transform` の scale がいくつか（1 のままなら `scaleFit()` が効いていない）

**上流へ出すことも選択肢である。** `refresh()` が中央寄せをしないことと、
`scaleFit()` が scroll を戻さないことは、**`mind-elixir` 側の非対称**である。
5.15.1 に固定している以上こちらで包む必要はあるが、原因の切り分けには使える。

**教訓（この一件から）**

- **画面の色の差は寸法の手がかりになる。** 「無駄な黒い余白」と見えていたものは
  装飾ではなく要素の境界だった。「空いている」で済ませず、
  **どの要素の背景が見えているのか**を問うこと

  4往復かかった。** 先に実測値を取れば1往復で済んだ
