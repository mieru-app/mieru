# 要望の前提を実測した記録（2026-09-02）

**種別: アイディアドキュメント（記録）。正本ではない。**
確定した内容は `docs/design/` にある。ここは「なぜそう決めたか」を残す場所であり、
書かれた時点の事実である。**現在の仕様として読まないこと。**

**要望を実装に落とす前に、前提を実測すること。**
Phase 2.5〜2.10 の起案時、要望の前提が2件とも誤っていた。
`parse` → `serialize` を通せば数分で分かることだった。

---


要望の前提が実装と食い違っていたため、`parse` → `serialize` を実際に通して確認した。

| 確認したこと | 結果 |
|---|---|
| Markdown の表 | **消えない。** `remark-gfm` を入れていないため表は段落として解析され、ノートに逐語で入り冪等に往復する |
| インライン記法（`**` `` ` `` `~~` `[]()`） | **消えない。** ラベル文字列としてそのまま往復する。**ただし `\*` のようなエスケープは失われる**（2026-09-04 に判明。下記） |
| 引用（`>`）とコードブロック | **破棄される。** 警告は `parse()` が積んでいるが UI が捨てている |
| キャンバスのドラッグ移動 | `mind-elixir` の `draggable` は既定で有効。`moveNodeIn` は `operation` で拾えている（実機未確認） |
| ノードへの記法描画 | `mind-elixir` 5.15.1 に公式の `markdown` オプションがある。編集時は生の `topic` を別の入力欄に出すため、表示上消えた記号が編集で戻る |

**したがって「表を取り込みたい」「Markdown 記法を表したい」は保存側の課題ではなく表示の課題であり、
設計書 6.4 の正規化規則にも 6.5 のラウンドトリップ強保証にも触れない。** 当初この2件を
「生命線に触れる唯一の要望」と見積もっていたが、実測により取り下げた。


---


| 論点 | 決定 |
|---|---|
| 変換警告の表示（設計書11章） | **実装しない。** 利用者が1人であり、警告を読む手間に見合わない |
| キャンバスの「親子関係の入れ替え」の意味 | ドラッグ移動ではなく**親子の反転**（A の下の B を、B の下の A にする） |
| 履歴の置き場所 | `MapStore` に足さず、**`HistoryStore` として同じ層に別インターフェースを置く** |
| スマートフォン対応の方法 | ネイティブアプリを作らず、`GitHubStore` ＋ レスポンシブで対応する |
