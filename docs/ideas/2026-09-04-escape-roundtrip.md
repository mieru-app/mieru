# インラインのエスケープが往復しない（2026-09-04・未解決）

**種別: アイディアドキュメント（記録）。正本ではない。**
確定した内容は `docs/design/` にある。ここは「なぜそう決めたか」を残す場所であり、
書かれた時点の事実である。**現在の仕様として読まないこと。**

**未解決の課題である。** `\*` と書いた「文字としての星」が、保存すると強調記号に変わる。
ラウンドトリップの**強保証は破れていない**が、他人が書いた `.md` を開いて保存すると内容が変わる。
**直す前に、非正規化の `.md` を開く頻度を測ること。**

**IMPORTANT: インラインのエスケープが保存で失われる。未解決である。**

Phase 2.10 に着手する前に `parse` → `serialize` を通したところ、
**`\` によるエスケープが `\\` を除いて全て失われる**ことが分かった。ラベルでもノートでも起きる。

| ファイル上 | ラベル | 書き戻し | 往復 |
|---|---|---|---|
| `\*star\*` | `*star*` | `*star*` | **失う** |
| `\_under\_` | `_under_` | `_under_` | **失う** |
| `` \`tick\` `` | `` `tick` `` | `` `tick` `` | **失う** |
| `\[bracket\]` | `[bracket]` | `[bracket]` | **失う** |
| `\&amp;` | `&amp;` | `&amp;` | **失う** |
| `\~tilde\~` `\(paren\)` `\!bang` `\#hash` `\<angle\>` | 記号のみ | 記号のみ | **失う** |
| `a\\b` | `a\b` | `a\\b` | 保つ |

**意味が変わるのは `*` `_` `` ` `` `&` `~` `[` `!` である。** 「文字としての星」と書いたものが
強調記号になり、`\&amp;` と書いたものが実体参照になる。

**原因は解析側にある。** `parse.ts` はラベルとノートを組み立てるときに
`unescapeMarkdown()` を掛けており、**情報はモデルへ入る前に消えている。**
シリアライザ側の `escapeLineStart()` は行頭だけを再エスケープするため、対が成立していない。
`\\` だけが往復するのは、この1つだけ両側に規則があるためである。

**ラウンドトリップの強保証（設計原則5）は破れていない。** 保証の対象は
**正規化** Markdown であり、`*star*` を入れれば `*star*` が出て安定する。
壊れるのは**非正規化の `.md`（＝他人が書いたファイル）を開いて保存したとき**であり、
Phase 2.6 で GitHub 上のファイルを開けるようにしたことで現実の経路になった。

**Phase 2.10 はこの原因ではないが、症状を目に見えるようにする。** 記法を描くようになると、
`\*star\*` と書いた枝が斜体で表示される。**これまでは字面のまま出ていたので気付けなかった。**

**直すなら解析側である。** `unescapeMarkdown()` を掛けないか、元の綴りを別に保つ。
どちらも設計書 6.3・6.4 の改定と、プロパティテストの 20 万件以上の再実行を伴う
（`.claude/rules/core-engine.md`）。**着手する前に、非正規化の `.md` を実際に開く頻度を測ること。**
頻度が低ければ、直す価値より壊す危険が上回る。
