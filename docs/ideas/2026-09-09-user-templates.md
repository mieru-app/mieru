## 1. 結論

**「テンプレートとは、`template` タグの付いたマップである」と定義する。**

- 新しい仕組みを作らない。**テンプレートはただのマップ**で、一覧に並び、開いて直せる
- 新規作成画面には、`template` タグを持つマップが**その表題で**並ぶ
- そこから作ると、枝・ノート・配色・折り畳みを写し、**表題を差し替え、`template` タグを外し、日付を今にする**
- テンプレートにするには、コマンドパレットから「テンプレートにする」を選ぶ。
  **他のエディタで `tags: [template]` と書いても同じ**である

**保存形式・変換エンジン・`MapStore` の契約は1つも変えない。**

「組み込みの SWOT を自分好みに直したい」も同じ道で足りる。
**SWOT から作り、直し、テンプレートにする。** 組み込みを編集する仕組みは要らない。

## 2. 実測 — いまの仕組み

| 事実 | 出典 |
|---|---|
| テンプレートは `src/state/templates.ts` に**コードで固定**されている（空・SWOT・議事録・週次）。本文は言語表（`strings/ja.ts` など）にある | `templates.ts` |
| 作成は `createMap(title, md)` → `retitle(md, id, title, at)`。**`retitle` は表題と H1 と `updated` だけを差し替え、`tags`・`created`・`mm:` はそのまま通す** | `workspace.ts:218` |
| **タグを書く経路が `src/` に1つも無い。** 読むだけ（検索の絞り込みとサイドバーの数） | `grep "tags:" src` |
| `MapStore.list()` は `tags` を返す。**本文を別に読む必要が無い**（ローカルは frontmatter を読んで返し、GitHub は sha でキャッシュする） | `LocalFolderStore.ts:104`・`GitHubStore.ts:279` |
| 保存先は**直下の `.md` だけ**を見る。ドットで始まる名前は無視する。README でもそう約束している | `LocalFolderStore.ts:75` |
| **frontmatter の未知のキーは保存時に落ちる。** 読むのは `title` `tags` `created` `updated` `mm` だけ | `frontmatter.ts` |
| コマンドパレットは既に `kind: "template"` の項目を持ち、入力があるときだけ出す | `command-palette.ts:55` |
| 作成画面のテンプレートは**名前だけ**を出す。副説明は 2.12 で削った | `HomeScreen.tsx:87` |

### 副産物: テンプレートから作ったマップに `created` が無い

```
retitle(templateMarkdown("swot"), "x.md", "新しいマップ", at)
→ title: 新しいマップ
  updated: 2026-09-09T00:00:00.000Z     ← created が無い
```

組み込みテンプレートは frontmatter を持たないため、`retitle` が `created: ""` を
通し、`serializeFrontmatter` が空を省く。**空のマップから作った場合には入る**
（`initialMarkdown` が入れる）。実害は小さい（一覧は `updated` で並ぶ）が、
**今回の作業で自然に直る**（3章の「写すときに日付を今にする」）。

## 3. 設計案 — テンプレート＝`template` タグ

### 置き場所は「マップと同じ場所」以外に無い

| 案 | 判定 | 理由 |
|---|---|---|
| **A. マップと同列の `.md`。タグで識別** | **採る** | 新しい仕組みが要らない。GitHub 保存先でも、ゲストモードでも、Obsidian からでも同じに動く |
| B. frontmatter に専用キー `template: true` | 採らない | 未知のキーは**保存時に落ちる**ので、読み書きを両方足すことになる。`MapMeta` が変わり、3つの保存先の実装と往復テストに触る。得られるのは「タグより明示的」だけ |
| C. `templates/` という下位フォルダ | 採らない | 「直下の `.md` だけ」という README の約束と保存先の設計を破る |
| D. ブラウザに保存（localStorage / IndexedDB） | 採らない | **原則1に反する。** 端末を替えると消え、他のツールから見えない |

**B と A の違いは「タグか、キーか」だけである。** タグは既に往復し、既に一覧に返り、
既に他のエディタで編集できる。**足す物が無い方を採る。**

### 識別子は `template` の1語に固定する

`mm:` と同じ扱いの**予約語**である。日本語の別名（`テンプレート`）を受けるのは
1行で書けるが、書き出すときにどちらを使うかの判断が要る。**まず1語にし、
要望が出たら別名を足す。**

### 作るときに何を写し、何を変えるか

| 項目 | 扱い | 理由 |
|---|---|---|
| 枝・ノート | 写す | テンプレートの本体 |
| `mm.colors`・`mm.collapsed` | 写す | 木が同じなので折り畳みのパスも有効。**配色を持てるのがテンプレートの利点** |
| `tags`（`template` 以外） | 写す | 「議事録」テンプレートに `meeting` タグが付いていれば、作った物にも付く |
| **`tags` の `template`** | **外す** | 外さないと、**作った物が全てテンプレートになる。** 一番の落とし穴 |
| `title`・H1 | 差し替える | いまと同じ |
| `created`・`updated` | **今にする** | 副産物の修正を兼ねる |

### テンプレートにする経路

**コマンドパレットに「テンプレートにする / テンプレートから外す」を置く。**
開いているマップのタグに `template` を足す・抜くだけである。

**設定画面には置かない。** 設定は端末ごとの好みの置き場所で、
マップの属性ではない（`settings-sheet-keep-minimal`）。
**画面にボタンも足さない。** 新規作成のたびに使う物ではない。

これが**タグを書く最初の経路**になる。書くのは `src/state/` で、
`store.read → タグを足す → store.write` の1往復である。

### 並び順

```
デフォルト → 自分のテンプレート → 組み込み（SWOT・議事録・週次）
```

自分で作った物は、選ぶつもりで作った物である。組み込みより前に出す。
自分のテンプレート同士は**表題順**（更新順にすると、直すたびに位置が変わる）。

### 組み込みテンプレートは残す

`templates.ts` の注記に「中身は暫定。実際に使って要らない枝が分かったら削る」とある。
**利用者テンプレートができれば、組み込みは減らせる。** ただし今回は触らない。
「デフォルト」だけにするかは、使ってから決める。

## 5. 気をつける点

| 状況 | 扱い |
|---|---|
| 作成画面で選んでいたテンプレートが（別のエディタで）消えた | 「デフォルト」へ倒す。エラーにしない |
| 組み込みと同じ表題のテンプレートを作った | 両方出る。id が違う（`swot` と `swot.md`）ので衝突しない |
| テンプレートを改名した | id（ファイル名）が変わる。作成画面は一覧を引き直すだけ |
| 既に別の意味で `template` タグを使っていた | そのマップがテンプレートとして出る。**害は無い**（作れるようになるだけ） |
| ゲストモード | `MemoryStore` も `tags` を返す。同じに動く |
| GitHub 保存先 | タグは frontmatter にあり、`list()` が返す。**追加の往復は無い** |
| パレットに同じマップが2回出る（「開く」と「この下敷きで新規作成」） | 意図どおり。組み込みも同じ扱い |

## 7. 判断が要る点

1. **テンプレートにする経路をパレットだけにしてよいか。** 見つけにくいが、画面は増えない。
   代案は「開いているマップの名前の横に印」だが、UI が増える
2. **並び順。** 自分のテンプレートを組み込みの前に出す案で進めてよいか
3. **README に1行足すか。** 「テンプレートは `template` タグを付けたマップです」。
   他のエディタから作れることを伝えられる
