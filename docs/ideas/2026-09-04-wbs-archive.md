**プロパティテストが検出した往復破壊（いずれも単体テストでは到達し得ない入力）**

| 事象 | 原因 |
|---|---|
| 空白のみのノートが空行として出力され消える | パーサ側だけが正規化しており、シリアライザと非対称だった |
| `<html>` で始まる行が破棄される | HTMLブロックとして解析され段落にならない |
| ルートの絵文字が往復で増える | frontmatter の title 由来の絵文字を H1 で上書きしていなかった |
| 空ラベルの子ノードが親のノートに吸収される | 空の箇条書きは段落を中断できない（CommonMark） |
| `=` のみの行が直前の行を見出しに変える | setext 見出しの下線は1文字でも成立する |
| `0x0` などのタグが消える | YAML では16進数として数値に解釈される。引用符判定を正規表現で行っていた |
| ラベル `! #` が `!` になる | ATX 見出しの閉じシーケンスとして末尾の `#` が除去される |

後半2件は10万件規模の実行で初めて再現した。**プロパティテストの実行回数を1万件で固定せず、変換規則を変更した際は一時的に数十万件まで上げて確認すること。**

キャッシュ優先）しかなく、設定の面を増やす割に得るものが少ないためである。
これ以上増やしたくなったら導入を検討する。

**解決済み: ラウンドトリップのプロパティテストが1度だけ落ちた件（2026-09-02 → 2026-09-04）。**
2026-09-04 の CI（Phase 2.8 の push）で再現し、正体が分かった。

落ちていたのは 10,000 件のテストではなく、同ファイルの
**「表示状態を本文へ書き出さない（設計原則2）」** である（1,000 件）。
所要が 9.18 秒と短かったのは、10,000 件のテストではなく後続の軽いテストで
止まっていたからで、**「実行基盤の一過性の失敗」という当時の見立ては誤りだった。**

**原因はテスト側にあり、製品は壊れていなかった。** 検査が
`expect(body).not.toContain("mm:")` と書かれており、**利用者がノートに `mm:` と
書いた場合を違反として数えていた。** 逐語で残るのはラウンドトリップの強保証そのもので、
正しい動作である。`docArb` がその文字列を生む確率が低かったため、稀にしか落ちなかった
（CI の反例は seed `-2088454712`、ノートが `"mm:

"`）。

**直し方: 字面ではなく性質で確かめる。** 原則2が言っているのは置き場所なので、
**「表示状態だけを変えたとき、本文が1バイトも変わらない」**を検査に改めた。
併せて、表示状態を丸ごと捨てても本文は一致してしまうため、折り畳みが frontmatter 側に
現れることも見ている。20万件で通過を確認済み。

**教訓: 「文字列が含まれていないこと」で不変条件を確かめない。** 利用者の入力は
どんな字面にもなり得る。禁止したいのが置き場所なら、置き場所を変えて比べる。

**`src/features/` は作らないことにした。** 計画では 2-3 を `src/features/search/` としていたが、
検索の判断（正規化・AND 条件・並べ替え）は自動テストの対象にしたい一方、`src/features/` は
描画層の規約（`.claude/rules/ui.md`）が掛かる場所である。判断を `src/state/search.ts`、
描画を `src/views/Sidebar/` に分け、`CLAUDE.md` の層の表と一致させた。

**2.6-1 は 2026-09-03 に完了した**（[検証メモ](../human-review/github-api-verification.md)）。
