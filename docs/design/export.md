## 7.3 テキスト出力


「AIにインプットするドキュメントとして簡単に出力する」という要件の中核機能。
**形式**と**範囲**の2軸で選ぶ。frontmatter はどの組み合わせでも出力しない。
表示状態（折り畳み・配色）をAIに渡さないためである（設計原則2）。

| 軸 | 選択肢 | 既定 | 型 |
|---|---|---|---|
| **形式** | 見出し / 箇条書き | 見出し | `ExportFormat` = `"heading"` \| `"bullet"` |
| **範囲** | 全体 / 選択部分 | 全体 | `ExportScope` = `"whole"` \| `"selection"` |

**範囲は `src/core/` に持ち込まない。** 変換エンジンが受け取るのは「どのノードから出すか」
（構造パス）だけであり、「いま選択中かどうか」は `src/state/` が解決する。
選択は編集状態であって変換の入力ではない。

#### 形式1: 見出し（既定）

第1〜第3階層を Markdown 見出し（`##` / `###` / `####`）に昇格させ、それ以降を箇条書き、ノートを本文段落として展開する。**LLMが最も文書として解釈しやすい形**であり、既定値とする。

```markdown
# 新規事業の論点整理

## 市場

### TAM試算

既存レポートでは1,200億円。ただし定義が広すぎる疑いがある。
自社が取りうる範囲に絞ると300億円程度と見るのが妥当。

### 競合の空白地帯

## 自社の強み

### 既存顧客基盤
```

#### 形式2: 箇条書き

frontmatter を除去した本文をそのまま出力する。構造をコンパクトに伝えたいときに使う。

```markdown
# 新規事業の論点整理

- 市場 🌏
  - TAM試算
    既存レポートでは1,200億円。ただし定義が広すぎる疑いがある。
  - 競合の空白地帯
```

**この形式は保存と同じ関数（`serializeBody()`）から出す。** 出力用に書き直すと正規化規則が
片方だけ古くなり、「保存した `.md` と出力した `.md` が違う」という、最も気づきにくい
食い違いが起きる。

#### 範囲

「選択部分」は選択中のノードを起点とする部分木のみを出力する。論点ごとに分けてAIへ投げたいときに使う。

**中心テーマを選んでいるときは全体を出す。** 「部分のつもりで全体が出た」より「全体が出た」と
分かる方がよいため、出力パネルは対象（「全体」または起点ノードのラベル）を常に名前で示す。

#### 2軸に改めた経緯（Phase 2.5、2026-09-02）

当初は「そのまま」「見出し展開」「部分出力」の3モードを1列に並べていた。**性質の違うものを
同格に見せていた** — 前2つは「どんな形式で書くか」、3つ目は「どこまでを出すか」である。
実利用で「何を選べばよいか分からない」という指摘が出たため、2つの軸に分解した。

出力される Markdown 自体は変えていない。「見出し × 選択部分」は旧モード3に、
「箇条書き × 全体」は旧モード1に等しい。**新たに「箇条書き × 選択部分」が選べるようになった**が、
これは分解の副産物であり、機能追加を目的としたものではない。

#### 名称（Phase 2.5 で変更）

ツールバーのボタンは「AI 用に出力」から**「テキスト出力」**へ改めた。
「AI 用」は用途の説明であって動作の説明ではなく、押すと何が起きるかが伝わっていなかった。
出力先がAIであることは利用者が決めることであり、ボタンが名乗る必要はない。
#### 操作

| 操作 | 結果 |
|---|---|
| `Ctrl+Shift+C` | 既定（見出し × 全体）でクリップボードへコピー |
| ノード選択 + `Ctrl+Shift+C` | 見出し × 選択部分でコピー |
| ツールバーの「テキスト出力」 | 形式と範囲を選び、結果を見てからコピー／`.md` で保存 |

**出力パネルは結果をそのまま出す。** 選択肢の違いは説明より現物を見た方が早く、
何が渡るのか分からないまま貼り付けるのが、この道具でいちばん困る状況であるため。

#### 逆方向（Phase 2.5 で追加）

AI が整理した結果を Mieru で開けるよう、**Mieru が読める Markdown を書かせるための指示文**を
アプリからコピーできるようにする。置き場所は新規作成画面とする。出力パネルではない。
マップをまだ持っていない状態で使うものであり、出力パネルは開いているマップが前提だからである。

**指示文は文書ではなくコードに置く**（`src/state/import-prompt.ts`）。指示文に載せた例文が
実際に取り込めることを自動テストで確かめられるようにするためで、変換規則を変えたときに
指示文だけが古くなる食い違いが構造的に起きない。
