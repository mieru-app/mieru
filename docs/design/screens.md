# 画面

**モード3つ・ツールバー1本・モーダル原則禁止。**
書き換える画面が2つ（キャンバス・アウトライン）、読む画面が1つ（Markdown）。

機能 ID とキー操作は [機能一覧](./features.md)。実装は `src/app/` と `src/views/`。

**節番号は分割前のものを残してある。** コード中のコメントが
「設計書 8.6」のように章番号で参照しているため（49 ファイル・92 箇所）。
対応は [設計の索引](../design.md)。

## 7.2 画面設計


**原則4・原則5に基づき、画面はモード3つ・ツールバー1本に限定する。モーダルダイアログは削除確認を除き使用しない。**

**モードの内訳は「書き換える画面が2つ、読む画面が1つ」である**（Phase 2.8 で Markdown を追加、F-25）。
キャンバスとアウトラインは同じ木を別の形に描いたもので、どちらからも編集できる。
Markdown は保存されるバイト列をそのまま出す読み取り専用の画面であり、**編集の入口を持たない。**
書き換えられる画面かどうかは `src/state/view-mode.ts` の `isEditableMode()` が持ち、
ノートパネルと編集バーを出すかどうかもそれで決まる（`src/state/layout.ts`）。

```
┌──────────────────────────────────────────────────────────────┐
│ Mieru  新規事業の論点整理 [キャンバス|アウトライン|Markdown] ⚙│ ← ツールバー1本
├────────────┬─────────────────────────────────┬───────────────┤
│            │                                 │               │
│ 🔍 検索    │                                 │  ノート        │
│            │        ┌──────┐                 │  ──────────   │
│ ▸ 最近     │   ┌────│ 市場 │────┐            │  既存レポート  │
│  新規事業… │   │    └──────┘    │            │  では1,200億  │
│  読書メモ… │ ┌─▼──┐         ┌───▼──┐         │  円。ただし…  │
│  週次振返… │ │TAM │         │空白地│         │               │
│            │ └────┘         └──────┘         │  （選択ノード │
│ ▸ タグ     │        ┌────────┐               │   がある時    │
│  #strategy │   ┌────│中心テーマ│───┐          │   のみ表示）  │
│  #reading  │   │    └────────┘   │          │               │
│            │ ┌─▼───┐         ┌───▼──┐        │               │
│ + 新規作成 │ │ 強み │         │リスク│        │               │
│            │ └─────┘         └──────┘        │               │
├────────────┴─────────────────────────────────┴───────────────┤
│ ✓ 保存済み 14:32         1000ノード        Ctrl+K でコマンド  │ ← ステータスバー
└──────────────────────────────────────────────────────────────┘
  ↑ サイドバー(Phase 2)      ↑ 主表示領域            ↑ ノートパネル
```

- **サイドバー**: `Ctrl+B` で開閉。マップの数が少ないうちは畳んでおける
- **主表示領域**: キャンバス／アウトライン／Markdown が同じ場所で入れ替わる。選択ノードは切替後も維持される
- **Markdown 表示**: 保存される全文（frontmatter を含む）を等幅で出す。折り返さず横に送る。
  **保存と同じ `serializeMarkdown()` から出す** — 表示用に書き直すと「保存した `.md` と
  見せた `.md` が違う」という、最も気づきにくい食い違いが起きる
- **ノートパネル**: ノートを持つノードを選択したときのみ表示。常時表示しないことで画面を広く保つ。
  **Markdown 表示では出さない** — 全文をそのまま出している隣に同じノートを編集できる欄を並べると、
  どちらが正なのか見た目では決められなくなる
- **ステータスバー**: 保存状態を常時表示。「保存ボタンを探す」体験を作らない（原則4）
- **一覧と欄の幅は利用者が変えられる**（Phase 2.11、2026-09-04 の実利用要望）。
  境目を掴んで動かすか、`←` `→` で調整し、`Home` で既定へ戻る。
  **保存先は `localStorage`** — マップごとの表示状態ではなく端末ごとの好みなので、
  frontmatter の `mm:` には書かない（原則2）。配色と同じ扱いである。
  可動域と既定は `src/state/pane-size.ts` が持ち、**掴んだ向きに対してどちらが
  広がるかもそこにある**（一覧と欄で符号が逆になる）
- **履歴パネル**（Phase 2.8）: ノートパネルと同じ場所に出る欄の1つ。ツールバーの「履歴」と
  コマンドパレットから開く。**キー割り当ては持たない** — `Ctrl+H` はブラウザの履歴に
  取られており、奪うと利用者の他の操作を壊す。**狭い画面では設定シートが唯一の行き先になる**
  （ツールバーに入らないため。7.2.1 のテキスト出力と同じ扱い）
- **設定シート**: 「一度決めたら滅多に変えない」ものだけを置く（原則4）。
  ただし**ソースコードへのリンクはここに置く**（2026-09-06）。設定ではないが、
  「疑うなら読める」は本ツールの信用の説明そのものであり（[安全](./security.md) NF-43）、
  **README にしか置かなければ、画面から入った人には届かない。**
  URL は `src/state/project.ts` が持ち、`package.json` の `repository` と
  一致していることをテストで縛る。**行き先がずれると、確かめに来た人を別の場所へ送る**

**新規作成とホーム画面は主表示領域に出す（Phase 2.5 で追加）。**
初期実装はサイドバーの一覧に入力欄を差し込む方式だったが、既存のマップと見分けが付かず、
狭い欄に下敷きの選択と表題の入力を詰め込むことになっていた。かといってモーダルにはしない
（上の原則）。**マップを開いていないときの主表示領域は空いている**ため、そこへ出す。
ホーム画面（オンボーディング）も同じ場所に同居させ、1つの画面として作る。

**モーダルを避ける方針は変えていない。** 削除確認以外でモーダルを使わないのは、
思考の流れを止めないためである（原則4）。主表示領域を使えば、この制約を守ったまま
入力に必要な広さが得られる。

#### 7.2.1 狭い画面（Phase 2.7 で追加）

**サイドバー 15rem とノートパネル 20rem は固定幅で、足すと 560px ある。**
スマートフォンは 360〜390px なので、列として並べたままでは主表示領域に回る幅が残らない。
**列をやめて、開いたものを主表示領域の上に重ねる。**

| ペイン | 狭い画面での出し方 | 理由 |
|---|---|---|
| 主表示領域 | 常に全幅。**覆われている間も外さない** | 外すと `mind-elixir` が破棄され、拡大率と位置が失われる |
| サイドバー | 全面に覆いかぶせる | 一覧は「移動」の操作であり、移動中に地図は要らない |
| テキスト出力・設定・キー操作 | 全面に覆いかぶせる | 同上 |
| ノートパネル | **下から 55% だけ** | 全面を覆うと、いま触った枝が見えないまま説明を書くことになる |

**同時に出せるのは1つなので、優先順位が要る。判断は `src/state/layout.ts` に置く。**

```
欄（テキスト出力・設定・キー操作） > サイドバー > ノート
```

- **欄がサイドバーより先に来るのは、押しても何も出ない操作を作らないためである。**
  サイドバーは主表示領域を覆うが、その上のツールバーは押せる。サイドバーが勝つと、
  一覧を開いたまま設定を押した利用者には「壊れている」としか見えない
- **サイドバーがノートより先に来るのは、ノートが選択に付随して開くためである。**
  ノートが勝つと、枝を選んだ後はサイドバーを開いた瞬間に覆われ、一覧に辿り着けない

**マップを開いたらサイドバーを畳む。** 覆ったままでは開いた先が見えない（`keepSidebarAfterOpen`）。
同じ理由で、**起動時のサイドバーは狭い画面では閉じておく。**

**ツールバーは8個から4個に減らす。** 残すのは ☰・ロゴ・表示切替・⚙ で、
外した3つには行き先がある（テキスト出力とキー操作は設定シート、新規作成は
サイドバーとホーム画面に元からある）。マップ名も外す。数文字で切れて意味をなさない。

**幅の境目を持つのは `NARROW_MAX_WIDTH`（40rem）ひとつだけにする。**
CSS のメディアクエリに同じ値を書くと、片方だけ直したときに黙ってずれる。
幅は `App.tsx` が測り、`:root[data-narrow]` として CSS へ渡す。

**キャンバスの手勢はライブラリに任せ、こちらは押しボタンだけを足す。**

`mind-elixir` 5.15.1 は pointer イベントで指も扱う。状態機械
（`Idle` / `Pinch` / `DragWait` / `Drag` / `Pan` / `BoxSelect`）を持ち、
指の場合は次のように分かれる。

| 触れた先 | 起きること |
|---|---|
| 地の部分 | そのままパンする（パン判定に `\|\| pointerType === "touch"` がある） |
| 枝の上 | **0.5秒の長押し**でドラッグ開始（`DURATION: 500` / `MOVE_THRESHOLD: 10`）。<br>先に動かすとパンへ落ちる |

**こちらが足すのは拡大縮小の押しボタン（＋／−／⛶）だけにする。**
`scale()` / `scaleFit()` を呼ぶだけで手勢は横取りしない。指しか無い端末に
拡大縮小の入口が要るためであり、ライブラリの手勢と競合しない。

#### パンを自前で持って失敗した記録（2.7-6 → 2026-09-04 に撤去）

**2.7 の実機確認で「指でマップが動かない」と出たため、自前のパンを足した。
その診断が誤りだった。**

- 根拠として引用した式は
  `!e.editable || t.button === o && t.pointerType === "mouse"` だったが、
  **実際には末尾に `|| t.pointerType === "touch"` が続いていた。**
  引用時に落とし、「マウス専用」と読み違えた
- 結果、**ライブラリのパンと自前のパンが同時に走り、地の部分では指の移動量の
  2倍だけ地図が動いていた。** 2026-09-04 に実機で確認（1cm 動かすと約2cm 進む）
- **不具合として現れるまで9か月ぶんの誤解が残り得た。** 自前パンが「効いている」
  ように見えたため、誤診が裏付けられたように錯覚した

**教訓: 最小化した引用でライブラリの挙動を断定しない。** 条件式は端まで読む。
そして**「自前で足したら直った」は、向こうが壊れている証拠にはならない。**
二重に効いていても、たいてい直ったように見える。

**構造編集の手段を画面に置く（2.7-5。実機で判明した）。**

**7.4 で「キー操作は本ツールが一手に引き受ける」と決め、`mind-elixir` の
右クリックメニューとツールバーを両方切った。デスクトップだけを見れば正しいが、
指しか無い端末には入口が1つも残らない。** 実機で確かめるまで、
スマートフォンでは**読むことしかできなかった**。

| 操作 | 割り当て | 指での代替 |
|---|---|---|
| 子を追加 | `Tab` | **無かった** |
| 兄弟を追加 | `Enter` | **無かった** |
| 名前を変える | `F2` | アウトラインのダブルタップのみ。キャンバスには無かった |
| 削除 | `Delete` | **無かった** |
| 元に戻す | `Ctrl+Z` | **無かった** |

**狭い画面のときだけ、ステータスバーの上に編集バーを出す。**
並べるのは ＋子・＋兄弟・名前・削除・取り消しの5つ。広い画面には出さない
（キーボードがあり、ツールバー1本の原則を崩す理由がない）。

- **取り消しを入れるのは、削除が指1本で起きるためである。** 部分木ごと消えるのに
  `Ctrl+Z` が押せない端末では、戻す手段が他に無い。削除だけ字の色を変えて区別する
- **出す・出さないの判断は `src/state/layout.ts`。** 一覧や欄が覆っている間は出さない
- **並べる操作と押せる条件は `src/app/edit-bar.ts` が持ち、自動テストを付ける。**
  `keymap.ts`・`shortcuts.ts`・`command-palette.ts` と同じ理由である。
  **この一覧が嘘をつくと、その端末では操作そのものが失われる**

**スマートフォン特有の落とし穴を3つ塞ぐ。**

| 現象 | 原因 | 対処 |
|---|---|---|
| 入力欄に触れるとページが拡大し、以後ずっと横にはみ出す | iOS Safari は 16px 未満の入力欄で自動拡大する。本文は 14px | 狭い画面では入力欄を 16px にする |
| ステータスバーが画面の外に出る | iOS Safari の `100%` は URL バーの分だけ実際の表示高より大きい | `body` を `100dvh` にする |
| 枝を下へ動かすとアプリが再読み込みされる | 引っ張って更新と見分けが付かない | `overscroll-behavior: none` |
