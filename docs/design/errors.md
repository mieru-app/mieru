## 11. エラー処理方針

| 事象 | 挙動 |
|---|---|
| フォルダ権限の失効 | 編集内容をIndexedDBへ退避 → ステータスバーに再許可ボタンを表示 → 許可後に自動で書き戻す |
| ファイルの外部変更を検知 | ステータスバーに通知。未編集なら自動再読込、編集中なら「再読込 / 自分の版を保持」を選択させる |
| 変換不可な要素を含むMarkdown | 該当要素は破棄する。**警告表示は行わない（2026-09-02 変更）** — 下記 |
| 保存失敗 | 3回まで指数バックオフで再試行。それでも失敗したらIndexedDBへ退避しエラーを表示 |
| 競合（Phase 3） | 8.5 に従い両方を保持 |
| 非対応ブラウザ | 起動時に検出し、対応ブラウザを案内する画面を表示（Phase 1のみ） |

**共通方針: 利用者の入力を失わせる挙動は、いかなる場合も許容しない。** 保存できない状況ではまずIndexedDBへ退避することを最優先とする。

**変換警告を表示しないと決めた経緯（2026-09-02）**

初版はこの警告を必須としていたが、実装されないまま Phase 2 まで来た。改めて検討した結果、
利用者判断により**実装しないこととした。** 利用者が1人であり、警告を読む手間に見合わないためである。

**ただし共通方針との緊張は残っている。** 実際に破棄されるのは引用（`>`）とコードブロックであり
（6.3 の実測）、これらは黙って消える。警告を出さない以上、消えることを防ぐ手段は
**逐語保持しかない**（未決。`docs/ideas/2026-09-04-escape-roundtrip.md`）。実利用で困った時点でそちらに着手する。
**「警告しない」は「消えてよい」ではない。**

`parse()` は現在も `warnings` を正しく積んでいる。UI が使わないだけであり、
方針を戻す場合に実装し直す必要があるのは表示側のみである。

## 描画中の例外

**例外1つで画面が真っ白になる状態を作らない。**
`src/app/ErrorScreen.tsx`（React のエラー境界）が受け止め、
何が起きたかを画面に出し、書きかけを写せるようにする。**これを外さないこと。**

2026-09-04 の実利用で「頻繁に落ちる」と報告があり、
何が起きたのか誰にも分からない状態だった。**原因を突き止める前に、まず見えるようにする。**
