## 8.8 HistoryStore（Phase 2.8）

過去の版を一覧し、差分を見て戻す（F-07）。

**`MapStore` に足さない。** あちらは「UI の都合でメソッドを追加してはいけない」と定めた
境界であり（8.1）、履歴閲覧はその契約に含まれない。同じ層に別のインターフェースとして
置くことで、**保存先ごとに履歴の実体を変えられる。**

| 実装 | 履歴の実体 | 版の id |
|---|---|---|
| `IdbHistoryStore` | IndexedDB に控えた `.md` | 採番した連番 |
| `GitHubHistoryStore` | リポジトリのコミット | コミットの sha |

```typescript
interface HistoryStore {
  list(mapId: string): Promise<HistoryEntry[]>;   // 新しい順。本文は読まない
  read(mapId: string, entryId: string): Promise<string>;
  record?(mapId: string, md: string, at: number): Promise<void>;
  forget?(mapId: string): Promise<void>;
  rename?(oldId: string, newId: string): Promise<void>;
}
```

**履歴は控えであって正本ではない。** `.md` が唯一の真実であることは変わらず（原則1）、
履歴はそこから導かれる控えとして扱う。**履歴の読み書きに失敗しても、マップの保存を
失敗させてはならない。** 控えられなかったことを理由に「保存できていない」と見せる方が有害である。

#### 8.8.1 控えるのは保存が成功した直後だけ

**保存が成功した瞬間だけが、実際に書かれたバイト列を確実に知っている場所である**
（`src/state/autosave.ts`）。ここ以外から控えると、保存に失敗した内容や、
そもそも保存されなかった内容が履歴に混ざる。

#### 8.8.2 何件・どの間隔で残すか

**素直に「保存のたびに1版」とすると履歴は使い物にならない。** 自動保存は入力停止から
800ms で走るため（F-31）、30分の編集で 100件を超え、一覧が「3秒前・5秒前・8秒前」で埋まる。
目当ての版を探せない一覧は、無いのと同じである。

判断は `src/store/history-policy.ts` に純粋関数として置く。

| 規則 | 値 | 理由 |
|---|---|---|
| まとめる窓 | 5分 | この間の保存は1つの版に畳む |
| 版数の上限 | 50版 | 5分に1版なので、およそ4時間ぶんの編集が残る |
| 総量の上限 | 1マップ 2MB | 版数だけで抑えると大きなマップで数十MBになる |
| 内容が同じ | 控えない | 折り畳みを開いて閉じただけでも保存は走る |

**窓は「その版をまとめ始めた時刻」から測る。取り込んだ最新の時刻から測ってはいけない。**
まとめるたびに窓が先へずれ、編集を続けている限り5分が永久に来ない。30分打ち続けても
版が1つしか残らなくなる。

**総量の上限を置くのは、IndexedDB を使い切ると退避（11章）まで書けなくなるためである。**
割り当てを決めるのはブラウザであり、控えのために「データを失わせない仕組み」を潰しては
本末転倒になる。

#### 8.8.3 一覧だけでは戻す判断ができない

**「14:32 の版」と言われても、それが枝を消す前なのか後なのかは中身を見るまで分からない。**
版を選んだら、今の内容との差分をその場に出す（`src/views/History/`）。

差分は行単位で、`src/state/diff.ts` に自前で置く。要るのが「行の追加と削除」だけであり、
単語単位の差分も3方向マージも使い道が無いためライブラリは入れない。
**前後の一致部分を先に落としてから突き合わせる** — 編集はたいてい大きな文書の一箇所であり、
丸ごと総当たりすると行数の積だけ時間がかかる。

**増減は色だけで示さない。** 行頭に `+` / `-` を常に出す。色覚の違いや白黒表示で読めなくなる。

#### 8.8.4 復元は木の差し替えであって、書き戻しではない

版を選ぶと、その内容を**編集中の木として差し替える**（`replaceTree`）。Undo スタックへ積むので
`Ctrl+Z` で取り消せる。**保存先へ直接書き戻さない** — 上書きしてしまうと、取り消す手段が無くなる。
書き込みは、いつもどおり自動保存に任せる。

**戻すのは枝とノートと折り畳みだけで、表題とタグは今のものを保つ。** 表題まで戻すと
ファイル名（id）が変わり、復元が改名（F-03）を巻き込む。

#### 8.8.5 マップが消えたとき・名前が変わったとき

- **削除したら履歴も消す。** 残すと、削除したはずの内容が利用者の端末に残り続ける
- **改名したら履歴を引き継ぐ。** F-03 は id（ファイル名）ごと変えるため、
  引き継がないと改名した瞬間に過去の版へ辿り着けなくなる

**どちらも `IdbHistoryStore` の話である。** `GitHubHistoryStore` は
`record` / `forget` / `rename` を持たない。マップを消しても過去の版がリポジトリに
残るのは git の性質であり、こちらで消せるものではない。**利用者にはリポジトリが
履歴を持つことを接続時に示してある**（8.7.2）。

#### 8.8.6 GitHub のコミットを履歴として読む（2.8-5）

`GET /repos/{repo}/commits?path={パス}&sha={ブランチ}&per_page=50` で版を取り、
`GET /contents/{パス}?ref={コミットの sha}` で本文を読む。

- **控えない。** 保存1回がコミット1つなので、履歴の実体は既にリポジトリの側にある。
  同じ内容を IndexedDB にも積むと、二重に持ったうえに片方だけが古くなる
- **`HistoryEntry.size` は返さない。** コミット一覧に各版の大きさは含まれず、
  出すには版ごとに本文を取りに行くことになる（50版で 1+N。8.7.8 と同じ理由）
- **「まだ何も無い」を異常として扱わない。** コミットの無いパスは 200 と空配列、
  コミットが1つも無いリポジトリは 409、消えたパスは 404 を返す。どれも版0件とする
- 遡る深さ（50版）は `IdbHistoryStore` の上限と揃える。
  **保存先によって遡れる深さが変わると、同じ画面が別のことを意味する**
