## 2.3 利用者と信頼の境界（Phase 2.6 で追加）

**当初は単一利用者を前提にしていたが、OSS として配信することに決めた（2026-09-03）。**
これはスコープの変更であり、いくつかの判断の前提が変わる。

| 項目 | 内容 |
|---|---|
| 利用者 | GitHub アカウントを持つ個人。人数に上限は無い |
| データの置き場所 | **各利用者自身の GitHub リポジトリ。** 開発者は他人のマップを見られない |
| 開発者が預かるもの | **無い。** サーバもデータベースも持たない（12.4） |
| 利用者が預けるもの | **配信元のオリジンに、自分のトークンを預けることになる**（8.7.2） |

**最後の行が信頼の境界である。** アプリは静的ファイルとして配られるだけだが、
利用者のトークンはそのオリジンの保管庫に入る。**したがって配信元のオリジンに何を置くかが、
利用者の鍵の安全に直結する**（8.6）。ここを守れないなら、他人に使ってもらってはいけない。

**前提が変わった判断。** 「利用者が1人だから」を理由にしていた決定は、
理由ごと見直す必要がある。変換警告を表示しない決定（11章）はその一つで、
**自分のマップなら失われた要素に見当が付くが、他人にはそれが無い。**
Phase 2.6 の実利用で再評価する。

## この境界から出てくる要件

要件そのものは [非機能要件](./requirements.md) にある。ここでは何を守るためのものかを述べる。

| ID | 要件 | 何を守るのか |
|---|---|---|
| NF-42 | 認証情報を平文で保持しない | **Phase 2.6 は IndexedDB に平文で置いており、字義どおりには満たしていない。** 権限と期間を絞ることで被害の上限を抑える。根拠と代償は [永続化](./persistence.md) 8.7.2 |
| NF-43 | 第三者のスクリプト・フォント・解析ツールを読み込まない | 外部リソースは他人のトークンの持ち出し口になる。**CSP でブラウザに強制させる**（[配信](./delivery.md) 8.6）。方針だけに頼らない |
| NF-44 | 配信オリジンに Mieru 以外を公開しない | GitHub Pages は `<名前>.github.io` が丸ごと1つのオリジンで、同居した別ページから保管庫を読める。**運用上の約束ではなく要件とする** |

## トークンの扱い

**トークン文字列を持つのは `src/store/github-auth.ts` だけにする。**
表示・記録には `describeCredential()` を使う。
**資格情報オブジェクトをそのまま `console.log` へ渡すとトークンが漏れる**ので、
これはどの層で書いていても効く。

## 通信先

**`api.github.com` だけである。** CSP で強制済み（`vite.config.ts`）。
別の接続先が要る変更をするときは、CSP を緩める前に
「本当にブラウザから直接通信する必要があるか」を先に問うこと。
