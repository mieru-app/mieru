## 6. 進め方

**各フェーズの完了時点で「実際に使える状態」になっていること。**
全部完成するまで使えない、という進め方は取らない。

**マイルストーンの間には必ず実利用期間を挟む。**
この期間に判明する使いにくさは、机上で考えた機能追加より優先度が高い。

**この方針は実際に機能した。** Phase 2 完了後の実利用から出た改修要望が Phase 2.5〜2.10 であり、
その過程で「表が消える」「記法が扱えない」という当初の見立てが**実測により誤りと判明した**
（[前提の実測](../ideas/2026-09-02-conversion-premises.md)）。
机上で計画していれば、消えていないものを救う作業に工数を割いていた。

**要望を実装に落とす前に、前提を実測すること。**

## 8. 運用

| 項目 | 方針 |
|---|---|
| バックアップ | 保存先が GitHub ならリポジトリそのもの。ローカルフォルダなら OneDrive 配下か Git 管理 |
| 復旧 | **`.md` ファイルそのものが成果物なので、ファイルを戻すだけで復旧できる** |
| 配信 | `main` への push で GitHub Actions が lint とテストを通してからビルドし、公開する |
| 依存の更新 | 四半期ごとに `npm audit` と更新確認。`mind-elixir` は 5.15.1 に固定 |
