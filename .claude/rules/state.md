# 編集ロジック層の規約

`src/state/` は編集操作・状態・自動保存を持つ。**UI を自動テストしない方針の裏返しとして、判断はすべてこの層に集める。**

| ファイル | 役割 |
|---|---|
| `tree.ts` | 木の編集の純粋関数。追加・削除・階層変更・並べ替え・移動 |
| `editor.ts` | 編集中マップの状態と Undo/Redo |
| `autosave.ts` | デバウンス保存、競合・失敗の扱い |
| `workspace.ts` | 保存先（ローカルフォルダ／GitHub）、マップ一覧、`MapStore` の生存期間 |
| `github-guide.ts` | トークン作成の案内。**安全の前提を伝える文面であり機能の一部**（設計書 8.7.2） |
| `commands.ts` | キー操作・ツールバーから呼ばれる操作の実体 |

## 依存の向き

- React に依存しない（`zustand` のストアは React 非依存で使える）
- `mind-elixir` に依存しない
- `MapStore` を使うのは `workspace.ts` と `autosave.ts` だけにする

この向きを守っている限り、描画層を丸ごと差し替えても編集の正しさは検証済みのまま残る。

## データを失わせない

**IMPORTANT: 「保存済み」と表示したなら、その内容は確実に書かれていなければならない。**

- 保存中に入った編集は検出し、保存済みにせず次の保存を予約する（`autosave.ts` の `#saveOnce`）
- 競合中は自動保存で上書きしない。利用者が明示的に選んだときだけ上書きする
- マップを切り替える前・画面を離れる前に必ず `flush()` する
- 保存に失敗しても例外を投げっぱなしにせず、必ず `SaveStatus` として残す

## 折り畳み状態

セッション中は **uid** で持ち、保存時にだけ構造パスへ変換する（`collapsedUidsToPaths`）。
パスのまま持つと、ノードを削除した瞬間に後続のパスがずれ、折り畳みが別のノードへ移る。

## テスト

- 木の操作を追加したら、同じコミットで `tree.ts` のテストを追加する
- 状態遷移は「戻したつもりが戻っていない」が最も損害が大きい。Undo/Redo は厚く確かめる
- 保存の失敗経路（競合・外部削除・書き込み失敗）は必ず1件ずつ検証する
