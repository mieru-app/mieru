# 変換エンジンの規約

`src/core/` は Markdown とモデルの相互変換を担う。**ここの不具合はデータの変質に直結する**ため、他のどの層よりも慎重に扱う。仕様の正本は `docs/design/data-format.md`。

## 絶対条件

**IMPORTANT: 正規化 Markdown → モデル → Markdown はバイト単位で一致しなければならない（冪等性）。** この性質を壊す変更は、テストが通っていても入れてはいけない。

## 出力の正規化規則

シリアライザは入力によらず必ずこの書式で出力する。ここが揺れると冪等性が崩れる。

| 項目 | 規則 |
|---|---|
| 箇条書き記号 | `-` に統一する |
| インデント | 半角スペース2つ／階層 |
| ノート | 親箇条書きのインデント + 2スペースの段落 |
| 見出し | 中心テーマの `# ` のみ。第1階層以降は全て箇条書きに正規化する |
| frontmatter キー順 | `title` → `tags` → `created` → `updated` → `mm` の固定順 |
| 空配列・未定義値 | frontmatter から省略する |
| 行末空白 | 除去する |
| ファイル末尾 | 改行1つで終端する |
| 絵文字 | ラベルの後に半角スペース1つを挟んで付与する |

## 設計上の制約

- **表示状態は frontmatter の `mm:` 配下にのみ出力する。** 折り畳み・配色・座標を本文へ書き出してはいけない。AI に渡す本文を汚さないための中核的な制約（設計原則2）
- ノードの永続 ID を本文に書き込まない。階層は構造パス（例 `1.0.2`）で表す
- インライン記法（強調・リンク等）はラベル文字列としてそのまま保持し、解釈しない
- `[[リンク]]` は `links` に収集するが、ラベル文字列からは除去しない（可逆性のため）
- 変換不可能な要素を破棄する場合は、必ず警告として呼び出し側に返す。黙って捨てない

## テスト

- 変更したら `npm run test:core` を実行し、**出力を示してから完了を報告する**
- 新しい書式や記法を扱えるようにしたら、対応するラウンドトリップのテストケースを同じコミットで追加する
- ラウンドトリップは fast-check のプロパティテストで検証する。個別ケースの単体テストだけで済ませない
- カバレッジ目標は90%以上
- **変換規則やエスケープを変更したら、プロパティテストの `numRuns` を一時的に 20万件以上へ上げて確認すること。** 既定の1万件では10万件規模でしか再現しない不具合を取りこぼす（実際に2件そうだった）
- プロパティテストが稀に落ちる状態を放置しない。シードが変わるだけで落ちるなら、**バグは製品かテストのどちらかに実在する。** どちらかを突き止めるまで閉じない
- **IMPORTANT: 「その文字列が含まれていないこと」で不変条件を確かめない。** 利用者の入力はどんな字面にもなり得る。実際 `not.toContain("mm:")` は、ノートに `mm:` と書いた利用者を原則2違反として数えており、稀にしか落ちないため2日間原因不明のままだった（`docs/design/testing.md`）。**禁止したいのが置き場所なら、置き場所を変えて2つを比べる**

## エスケープは行頭と見出し末尾だけに足す（2026-09-05 改定）

**IMPORTANT: 行の途中には一切触れない。** かつて解析側が `\` + ASCII 記号を
すべて外していたのに、出力側は行頭しか足しておらず対になっていなかった。
そのため**他人が書いた `\*star\*` が `*star*`（強調）に化けていた。**

**外す判定は「外してからもう一度エスケープすると元に戻るか」で書く。**
位置と条件を二重に書くと、片方を直したときに黙ってずれる。

- **`\` で始まる行には何も足さない。** 足すと `\\*star\*` に増える
- 見出し末尾の `\#` は**本数で区別する**。`a #` と `a \#` の両方を保つため
- 守るのは `md → モデル → md`。**`モデル → md → モデル` は正規化で寄る**
- **絵文字の分割は解析側と出力側で同じ関数を使う**（`normalize.ts` の `splitEmoji`）。
  片方だけが分けていたため `0  ⁉`（空白2つ）で強保証が破れていた

検証は `src/core/__tests__/foreign-file.test.ts`。
**他人が書いた `.md` を触る変更をしたら、必ずここにケースを足す。**
経緯は `docs/ideas/2026-09-04-escape-roundtrip.md`。

## 引用とコードはノートへ逐語で入れる（2026-09-05 追加）

**エスケープするのは「木の形を変えるもの」だけにする。**
`#` `- ` `1. ` `---` `<` `[a]:` は子ノードや見出しになるので `\` を足す。
`>` と柵と半角4つはノートの中の形しか変えないので**逐語で出す**。

**IMPORTANT: 判断は `note.ts` に集める。** 保存側（`serialize.ts`）・
読み込み側（`parse.ts`）・表示側（`block.ts`）が同じ関数を使うこと。
別々に書くと**「保存はできているのに画面に出ない」**食い違いが起きる。

- **対になっていない柵は逐語で出さない。** 閉じない柵は後続の行を——子ノードまで——
  飲み込み、**枝が黙って消える**（実測）。エスケープして文字にする
- **外す判定はノート全体で行う**（`unescapeNote()`）。柵が対かは1行では決まらない
- **行末空白の一括除去をしない。** コードの中の空白まで削るとバイト列が動く
- 塊の境目には必ず空行を入れる。解析側がブロックごとに取り出して繋ぐため

検証は `foreign-file.test.ts`。**「ノートに何を書いても枝の本数が変わらない」**を
性質として置いてある。逐語で出す以上、記号が構造として読み戻される危険が常にある。
経緯は `docs/ideas/2026-09-05-blockquote-code.md`。

## 未解決: 空ラベルの入れ子で往復が揺れる（2026-09-05）

`- *` のように**中身が箇条書き記号1つだけ**の行は、1周目で親子、2周目で兄弟になる。
空ラベルの前に入れる空行が、入れ子の親子関係を切るため。**3周目以降は安定する。**
詳細は `docs/ideas/2026-09-05-empty-label-nesting.md`。

**`roundtrip.test.ts` の `numRuns` を 25 万件へ上げると、これが反例として出る**
（既定の1万件では出ない）。**変更前のコードでも同じ**なので、
上げて落ちたときはまずこの形かどうかを見ること。

## パーサとシリアライザの非対称性

解析には `remark-parse`（mdast）を使い、**生成は自前実装する**。`remark-stringify` は出力書式が入力に依存して揺れるため使わない。
