# 変換エンジンの規約

`src/core/` は Markdown とモデルの相互変換を担う。**ここの不具合はデータの変質に直結する**ため、他のどの層よりも慎重に扱う。仕様の正本は `docs/design/data-format.md`。

## 絶対条件

**IMPORTANT: 正規化 Markdown → モデル → Markdown はバイト単位で一致しなければならない（冪等性）。** この性質を壊す変更は、テストが通っていても入れてはいけない。

## 出力の正規化規則

シリアライザは入力によらず必ずこの書式で出力する。ここが揺れると冪等性が崩れる。

| 項目 | 規則 |
|---|---|
| 箇条書き記号 | `-` に統一する |
| インデント | 半角スペース2つ／階層 |
| ノート | 親箇条書きのインデント + 2スペースの段落 |
| 見出し | 中心テーマの `# ` のみ。第1階層以降は全て箇条書きに正規化する |
| frontmatter キー順 | `title` → `tags` → `created` → `updated` → `mm` の固定順 |
| 空配列・未定義値 | frontmatter から省略する |
| 行末空白 | 除去する |
| ファイル末尾 | 改行1つで終端する |
| 絵文字 | ラベルの後に半角スペース1つを挟んで付与する |

## 設計上の制約

- **表示状態は frontmatter の `mm:` 配下にのみ出力する。** 折り畳み・配色・座標を本文へ書き出してはいけない。AI に渡す本文を汚さないための中核的な制約（設計原則2）
- ノードの永続 ID を本文に書き込まない。階層は構造パス（例 `1.0.2`）で表す
- インライン記法（強調・リンク等）はラベル文字列としてそのまま保持し、解釈しない
- `[[リンク]]` は `links` に収集するが、ラベル文字列からは除去しない（可逆性のため）
- 変換不可能な要素を破棄する場合は、必ず警告として呼び出し側に返す。黙って捨てない

## テスト

- 変更したら `npm run test:core` を実行し、**出力を示してから完了を報告する**
- 新しい書式や記法を扱えるようにしたら、対応するラウンドトリップのテストケースを同じコミットで追加する
- ラウンドトリップは fast-check のプロパティテストで検証する。個別ケースの単体テストだけで済ませない
- カバレッジ目標は90%以上
- **変換規則やエスケープを変更したら、プロパティテストの `numRuns` を一時的に 20万件以上へ上げて確認すること。** 既定の1万件では10万件規模でしか再現しない不具合を取りこぼす（実際に2件そうだった）
- プロパティテストが稀に落ちる状態を放置しない。シードが変わるだけで落ちるなら、**バグは製品かテストのどちらかに実在する。** どちらかを突き止めるまで閉じない
- **IMPORTANT: 「その文字列が含まれていないこと」で不変条件を確かめない。** 利用者の入力はどんな字面にもなり得る。実際 `not.toContain("mm:")` は、ノートに `mm:` と書いた利用者を原則2違反として数えており、稀にしか落ちないため2日間原因不明のままだった（`docs/design/testing.md`）。**禁止したいのが置き場所なら、置き場所を変えて2つを比べる**

## 未解決: インラインのエスケープが往復しない（2026-09-04）

**IMPORTANT: `\*` のようなエスケープは、`\\` を除いて全て失われる。**
`parse.ts` がラベルとノートに `unescapeMarkdown()` を掛けるため、
**情報はモデルへ入る前に消えている。** シリアライザ側は行頭しか再エスケープしないので対が無い。

**強保証は破れていない**（保証の対象は正規化 Markdown であり、`*star*` を入れれば安定する）。
壊れるのは**他人が書いた非正規化の `.md` を開いて保存したとき**である。
詳細と直し方の方向は `docs/ideas/2026-09-04-escape-roundtrip.md`。
**エスケープ規則に触るときは、まずこれを読むこと。**

## パーサとシリアライザの非対称性

解析には `remark-parse`（mdast）を使い、**生成は自前実装する**。`remark-stringify` は出力書式が入力に依存して揺れるため使わない。
